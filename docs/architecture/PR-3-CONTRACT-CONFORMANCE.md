# PR #3 — Contract freeze and executable conformance

**Milestone:** the next development milestone after the architecture-contract proposal in PR #2.  
**Status:** owner decisions A1–A9 resolved and T1–T6 selected; executable contract implementation remains outstanding. This document is a scope and acceptance contract, not evidence that implementation is complete.

## Objective

Turn the architecture proposals into precise, machine-checkable contracts before implementing another product UI feature or the production calculation host.

PR #3 is complete only when a contributor can validate representative Khwarizmi documents and RPC messages against versioned schemas, run language-neutral fixtures through the TypeScript contract suite, and reproduce the same expected outcomes without launching the desktop application.

## Scope

1. Resolve every normative open decision that affects the v1 document, expression, evaluation, units, and RPC contracts. Record each approved decision in an ADR; leave genuinely deferred capabilities explicitly out of v1.
2. Publish versioned JSON Schemas for the native document envelope, pages/layout regions/blocks, canonical expression AST, evaluation results/diagnostics, and JSON-RPC v1 requests, responses, and errors.
3. Define a language-neutral fixture manifest with stable IDs, contract versions, input payloads, expected outcomes, and stable diagnostic/error codes.
4. Add valid and invalid fixtures for document validation, AST structure, symbol/dependency semantics, substitution traces, unit/dimension behavior, RPC envelopes, and framing boundaries.
5. Implement TypeScript schema validators and deterministic contract tests. Expected fixture outputs must be reviewed artifacts, not generated by the implementation under test.
6. Test the RPC framing codec independently of Windows named pipes, including fragmented prefixes/payloads, multiple frames, malformed data, zero-length frames, and the configured maximum payload.
7. Add a fake-host integration test for request/response correlation, invalid methods/params, cancellation behavior, and transport failure.
8. Run the contract suite in CI without requiring Electron, the production calculation host, or a Python installation.

## Explicit non-goals

- No new worksheet UI, editor feature, theme, toolbar, or visual redesign.
- No broad BlockSuite integration work.
- No production calculation-host implementation.
- No production expression evaluator or full engineering function catalog.
- No Python worker implementation.
- No claim of Windows named-pipe security verification from platform-independent framing tests alone.
- No claim that structural-engineering calculations are validated by schema or protocol tests.

## Decision gate — resolved

Owner decisions A1–A9 and implementation choices T1–T6 are recorded in [PR-3 decision resolution](./PR-3-DECISION-RESOLUTION.md) and aligned with ADR-010 through ADR-018 in DECISIONS.md. The v1 boundaries are now selected: micrometre page geometry; scalar-only values; exact decimal/rational authored numbers with tagged approximations; tracked sequential reassignment and lexical block locals; unambiguous implicit multiplication; versioned built-in units with angle semantics; fixed 16 MiB RPC frames; process verification plus per-launch capability; and Python worker deferred.

The remaining gate is evidence, not owner approval: publish schemas, fixtures, validators, semantic and RPC tests, and CI coverage. Deferred constructs must have stable rejection codes.

## Deliverables

- [ ] Approved ADR updates for all v1 normative decisions.
- [ ] Versioned JSON Schemas with examples and compatibility notes.
- [ ] Language-neutral fixtures and a validated fixture manifest.
- [ ] TypeScript validators with positive and negative schema tests.
- [ ] Semantic fixtures for dependency ordering, cycles, substitutions, and stable diagnostics.
- [ ] Unit/dimension fixtures for the capabilities explicitly included in v1.
- [ ] RPC envelope and framing codec tests.
- [ ] Fake-host integration tests, including cancellation and disconnect cases.
- [ ] CI job that runs the contract suite independently of Electron and the production host.
- [ ] Documentation linking every frozen contract to its schema, fixtures, and tests.

## Acceptance criteria

PR #3 may be considered complete only when:

- No unresolved normative ambiguity remains in any schema marked stable for v1.
- Every fixture has a unique stable ID and an expected outcome.
- Both valid and invalid inputs are tested; errors are asserted by stable codes, not prose.
- The TypeScript implementation consumes the same language-neutral fixtures intended for future independent implementations.
- Tests are deterministic and do not require a running desktop app or production calculation host.
- CI executes the suite on every relevant pull request.
- Unsupported or deferred behavior is rejected explicitly and documented.
- The roadmap and architecture index link to the resulting schemas, fixtures, tests, and decision records.

## Sequencing and dependencies

PR #3 is stacked on the architecture-contract work in PR #2 and must not be merged ahead of its base. PR #1's Windows packaging investigation continues independently; its status is not replaced by this milestone. Worksheet UI and production calculation-host work remain gated on PR #3's acceptance criteria.
